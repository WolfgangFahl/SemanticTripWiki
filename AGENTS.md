# AGENTS.md - Guidelines for agents working in SemanticTripWiki

SemanticTripWiki shows [Reel Driven Development](https://wiki.bitplan.com/index.php/Reel_Driven_Development) (RDD) by example: a Semantic MediaWiki for trip documentation is specified by reels and set up with a one line install.

## Plan and ask before do
State the plan before any reading, modifying or running action and proceed only on a positive `go!`:
```
I understood that <ANALYSIS> so that I plan to <GOALS> by <ACTIONS> estimating <#> <ITEMS> to be worked on. confirm with go!
```

## Ground on the reels
* the reel is the specification - read its manifest `reel.yaml` with the hops, urls and summaries before proposing anything
* reels of this project: [2026-09-11 TripContext](https://rdd.bitplan.com/reels/2026-09-11-TripContext/), manifest [reel.yaml](https://rdd.bitplan.com/reels/2026-09-11-TripContext/reel.yaml)
* every issue points to the reel that specifies or shows it; a requirement without a reel is asked for, not guessed
* method and tools: [Reel Driven Development](https://wiki.bitplan.com/index.php/Reel_Driven_Development), [reel-driven-development](https://github.com/WolfgangFahl/reel-driven-development)

## Structure
* `scripts/setup` - the one line install: prerequisites, Canasta instance, Semantic MediaWiki, python tools, wiki content
* `sidif/` - the model masters MetaModel and TripContext in SiDIF
* `wikibackup/` - the wiki pages: generated by ypgen from `sidif/`, plus the context pages, the ProfiWiki base pages, the Main Page and `images/`
* `semantictripwiki/` - python package, no code yet
* `tests/` - unittest tests of the deliverables

## Commands
```bash
scripts/install      # pip install .
scripts/test         # unittest discover
scripts/blackisort   # isort, black, docformatter - before every commit
checkos -o WolfgangFahl -p SemanticTripWiki --local -v   # project compliance
```
Regenerate the wiki pages from the model:
```bash
ypgen --sidif sidif/TripContext.sidif -gf --targetPath wikibackup -nd
ypgen --sidif sidif/MetaModel.sidif -gf --targetPath wikibackup -nd
```

## scripts/setup style
* bash in the style of the BITPlan mp scripts: `#!/bin/bash`, header with author and date, `l_` locals, functions before one single `while [[ $# -gt 0 ]]; do case ... esac; shift; done` loop
* the messaging functions of mp `bash_messages` are copied into the script so that it works standalone via curl
* without arguments the script runs the setup; every step is idempotent - a second run leaves the wiki working the same way
* settings come from the environment: `CANASTA_DIR`, `TRIPWIKI_ID`, `TRIPWIKI_HOST`, `TRIPWIKI_CONTENT`, `HTTP_PORT`, `HTTPS_PORT`

## Python
* unittest with `basemkit.basetest.Basetest`, no pytest fixtures
* type hints and Google style docstrings on every public function, named return variable
* black and isort via `scripts/blackisort`

## Commits and tickets
* ticket first: a change refers to its issue, e.g. `refs #3`
* an LLM is never author or co-author: no Co-Authored-By line, no generated-with line and no vendor name in commits, pull requests or issues
* never put credentials, hashes or internal host names into the repository or an issue
